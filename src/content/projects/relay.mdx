## Problem

Most teams discover event delivery semantics only after the first incident. relay makes the trade-off visible: a small service that accepts events, stores them durably, and coordinates retries with clear delivery state.

## Shape

The project uses PostgreSQL as the source of truth and treats workers as replaceable executors. This keeps the debugging path simple: inspect the event row, understand the next action, and replay safely.

## What I would change

The next iteration would add a stronger schema registry story. The delivery mechanism is only half the promise; long-lived event contracts need first-class care.
