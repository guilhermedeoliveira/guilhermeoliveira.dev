Retries are unavoidable. Networks fail, workers crash, clients double-submit, and users press buttons twice because the interface gave them no reason to trust it.

## The contract

An idempotency key says: this operation has a durable identity. If the same identity arrives again, return the same outcome instead of doing the work twice.

## Where it belongs

Put the key at the boundary where duplicate side effects would hurt: payments, provisioning, invites, imports, and external API calls.

## The quiet win

Idempotency turns a class of incidents into ordinary control flow. That is the kind of boring I like.
